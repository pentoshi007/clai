# P3 — Durable profile compatibility

Status: implementation in progress; no optimized/default profile activation.

P2 receipt: `259f9f82fdfd95bd8403710cd37e9662311599ec` pushed to `origin/audit/token-efficiency-roadmap`; remote ref equality and clean tracking state observed.

Hypothesis: an explicit content-addressed manifest plus route bindings can retain legacy prompt/tool bytes across process/configuration changes and prevent silent profile substitution. Current `compactPromptModes` is memory-only; full/compact, native/text, vision and MCP shape affect the prefix. History JSONL preserves whole records, but SQLite payloads, save options and resume projections explicitly enumerate metadata and must carry bindings. The current prose-substring composition detector should become an explicit capability with identical output.

Compatibility constraint: some ordinary legacy histories have no full leading system prompt or durable route/compact provenance (including the noninteractive user/answer-only save). Guessing a binding would falsely promise old cache continuity; forcing a new prompt on all such resumes would break existing behavior. Therefore profile binding remains an explicit isolated-session path during development. Unbound ordinary histories keep the unchanged legacy path without a new mandatory prompt or a fabricated profile identity. Experimental bindings validate/fail closed before submission. This is not authorization to activate a new default for ambiguous histories; P6 must retain baseline if compatibility/cache gates remain unresolved.

Proof strategy: exact legacy renders and ordered catalogs for all shape combinations; mutation isolation, clear error on unknown/version/digest corruption; private JSONL/SQLite/save-queue/import/export/recovery round trips; actual fresh-process resume with changed config and downgrade rejection; current session/compaction/provider/permission tests; build/package and local overhead checks. No grants, clock, cwd, keys, project rules or task content enter the profile metadata.

## Verified implementation and boundaries

- Added small profile-state/legacy-manifest/binding modules. The manifest hashes exact legacy render variants and ordered canonical definitions. Each route reference includes its full shape and separate prompt/catalog/artifact/binding digests; route corruption, unknown versions/profiles, extra authorization metadata and any artifact mismatch fail closed. Cached internal trees are frozen; caller schemas are independently cloned. Cache ownership is session-weak and at most 128 bound route variants; no network or synchronous per-turn artifact reads.
- Routing accepts explicit session profile state. Provider/model/mode/native routes are distinct; compact, reliability, vision and catalog shape bind once and survive config changes, fallback/return and process restore. Ordinary unbound sessions retain existing behavior. The exact execution-coverage capability replaces the production prose substring check without editing `src/prompts/index.ts` or any legacy prompt/schema bytes.
- Added optional metadata through history records, JSONL/SQLite payloads, save/upsert (including omitted-field preservation), queue snapshots, store adapter, controller load/persist/reset, UI resume and fallback save. No allow-list or pentest grant is serialized. Corrupt metadata is retained in readable history, but validation occurs before the controller replaces active history or submits a bound request. There was no existing distinct history import/export command; record JSON transfer/hydration and recovery are tested rather than inventing a new command. Noninteractive user/answer-only histories remain unbound and compatible; no fabricated old-prefix mapping is attached.
- New tests cover 16 shape combinations, caller mutation, route/config/native/text/return, malformed/reference corruption, save queue isolation, ordinary old histories, actual fresh-process restore, JSONL, actual SQLite SQL through the production serializer, serialized record transfer and actual orphan-temp recovery. ## Performance and rollout decision

A 500-sample warmed distributed Node measurement recorded unbound prompt p50/p95 0.129/0.397ms, bound cached prompt 0.037/0.061ms; unbound schema selection 0.029/0.049ms versus defensive bound-schema copies 0.489/0.567ms; one-time first binding 35.9ms. These are isolated microbenchmarks, not task/provider latency proof. The explicit path is **not enabled for ordinary sessions**, so its added copy/startup cost does not pass a default-rollout gate. Do not label the faster cached render alone a performance win. P6 owns rejecting activation unless all aggregate gates pass.

## TE-022 scope and cache baseline

Declared available development route remains codex/gpt-5.6-luna native, thinking enabled/medium; the P1 A/A coding/security/workload lineage, failed attempts and provider-exact read tokens are retained. NVIDIA 400, OpenAI 401 and Gemini 503 routes remain blocked. No undocumented subscription eligible-prefix denominator or cold/warm external eviction behavior is invented. Comparable warm hit/reuse **is unestablished**, and TE-022's live denominator portion remains unchecked for the P6 decision. Deterministic zero-drift and unknown-eligibility rejection gates are implemented. Candidate rollout scope is empty; subsequent offline candidates may be evaluated/rejected but not activated from this evidence.

Decision: retain ordinary legacy default; ship only dormant explicit compatibility machinery and the byte-equivalent internal capability replacement. This is not blanket upgrade/downgrade cache continuity for ambiguous old histories. A prior build that lacks a referenced experimental profile must not resume it; unknown profile/version controls prove the current reader's fail-closed behavior, not that an old binary magically understands new metadata. No optimized bindings are created by default, so ordinary downgrade behavior is unchanged.
