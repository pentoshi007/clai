# Baseline responsibility and tool contracts

P0 owns structural coverage. Behavioral equivalence remains an independent P1/P4/P5 gate; a digest or a source heading is not proof that a model obeys an instruction.

## Instruction ownership

The authoritative machine-readable ledger is [legacy-contracts.json](evidence/legacy-contracts.json), generated by [token-contract-ledger.ts](../scripts/token-contract-ledger.ts). Every top-level section of both source prompts maps to a named obligation, existing deterministic test anchors and required coding/security/deterministic scenario IDs from [validation.md](validation.md). Source spans, section and paragraph digests ensure no paragraph is silently dropped while consolidating a candidate. Renderer/compact/native/text behavior is also protected by the exact `src/prompts/index.ts` digest and the assembled route fixtures.

The mapping test fails if a section has no owner, a linked test is missing, the source bytes change, or the tool catalog differs. These anchors protect structure and existing enforced behavior; P1 must independently verify the complete natural-task outcomes. In particular, broad code-style, current-research, confidentiality and adversarial-content responsibilities are not considered model-quality-proven merely because their mapped structural tests pass.

Candidate authors must refine the section's obligation into individual semantic facts before removing/consolidating prose. Preserve the original spans and annotate where each fact moves; do not replace a legacy hash to accept new content. Plan detail, project rules, selected skill bodies and engagement scope remain authoritative dynamic inputs, outside the static optimization budget.

## Tool ownership

Each of the 47 ordered definitions records canonical/wire identity, mutation/read-only/ask flags, full definition digest, full parameter digest and actual OpenAI wire-definition digest. The parameter digest covers nested `required` combinations, aliases, enums, defaults, units/descriptions and bounds; it is not a lossy list of argument names. Tool-purpose/continuation/evidence obligations are retained in [tool-catalog.md](tool-catalog.md); no removal or dispatcher replacement is permitted.

`test/context/token-contract-ledger.test.ts` protects the captured complete contract. Existing definition, security-contract, filesystem, terminal, MCP and provider tests remain required. Runtime validators remain authoritative: the known legacy `web.fetch.maxBytes` mismatch is intentionally retained here, with its correction reserved for the isolated candidate in TE-029. Locking a mismatch is compatibility protection, not endorsing it.

## Assembled synthetic coverage

[token-assembly-fixtures.ts](../scripts/token-assembly-fixtures.ts) exercises 64 combinations of coding/security/ask/plan, native/text, full/compact, MCP/no MCP and image/no image. It uses production classification, section building, workspace orientation, message composition, session-state refresh, request accounting and final chat serialization. Only environmental sensors, date, scope loading and session scratch are controlled in its test harness; config/storage is isolated by the existing Vitest setup and networking is rejected.

Inputs include project rules/context, skill catalog/body, detailed plan acceptance, synthetic scope, history and replayable reasoning. Plan and security fixtures assert those components survive in full. The environment is synthetic Linux `/project` with a fixed hour; this is not a capture of the owner's session or a provider dispatch. Complete request settings/bytes, images and artifacts are counted separately from canonical accounting. The fixture forces full/compact explicitly; it does not claim to reproduce every automatic budget decision or pending-job/receipt state (P1/D07 covers those).

[Entity-level measurements](evidence/assembly-baseline.json) contain counts/digests only. `estimatedTokens` is `ceil(JS string length / 3.3)` even on serialized bodies; it is not an exact tokenizer or provider usage. Accounting additionally includes framing, estimated image tokens and only replayable artifacts. Consequently canonical-accounting totals, summed content estimates and serialized-wire estimates intentionally differ. Unknown live input/output/cache/cost data stays unknown.

## Reproduction

Run the original simplified baseline unchanged:

```sh
node --import tsx scripts/measure-token-overhead.ts "$PWD"
```

Run the isolated full-assembly baseline to an absolute report path under the active session scratch directory:

```sh
node --import tsx scripts/measure-token-overhead.ts --assembled "$SESSION_SCRATCH/assembly.json"
./node_modules/.bin/vitest run test/context/token-assembly-baseline.test.ts test/context/token-contract-ledger.test.ts --reporter=dot
./node_modules/.bin/tsc -p tsconfig.token-audit.json
```

The `--assembled` mode runs the same deterministic fixture test using the installed Vitest runner; no application instrumentation, model-visible diagnostics or provider transport is added. It exits without printing a result if checks fail. The initial ledger was generated with `captureTokenContracts(process.cwd())` in an isolated config environment; do not regenerate the locked artifact to mask a failing legacy assertion.
