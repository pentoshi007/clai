# Quality metric definitions

Reviewed specification for every metric the refactor program gates on
(Phase 0, P0-05). The machine-readable counterpart is
[`scripts/quality/config.mjs`](../scripts/quality/config.mjs); the two must
change together. Thresholds come from
[instructions.md §8](instructions.md#8-quality-measurement-and-ratchets) and may
only be tightened.

## Toolchain

Every package is exact-pinned in `package.json` and the lockfile. No analyzer
transmits source, fixtures or reports off the machine.

| Capability | Tool | Version | Command |
|---|---|---|---|
| V8 coverage | `@vitest/coverage-v8` | 4.1.10 (matches Vitest) | `npm run quality:coverage` |
| Cyclomatic / cognitive / Halstead | repository-owned, TypeScript compiler API | TypeScript 6.0.3 | `npm run quality:report` |
| CRAP | repository-owned, joins the two above | — | `npm run quality:report` |
| Mutation | `@stryker-mutator/core` + `@stryker-mutator/vitest-runner` | 10.0.0 | `npm run quality:mutation` |
| Dead files / exports / dependencies | `knip` | 6.33.0 | `npm run quality:dead-code` |
| Duplication | `jscpd` | 5.1.0 | `npm run quality:duplication` |
| Type-syntax report | repository-owned, token-aware | TypeScript 6.0.3 | `npm run quality:report` |
| Physical lines | repository-owned | — | `npm run quality:report` |
| Public contracts | repository-owned | TypeScript 6.0.3 | `npm run quality:contracts` |

Complexity, type-syntax, line and contract analysis are implemented in this
repository rather than delegated to a plugin so that `.ts` and `.tsx` go through
the same compiler the build uses, function attribution stays stable across
extractions, and nothing leaves the machine.

## Scope

- **Measured production scope:** `src/**/*.ts`, `src/**/*.tsx`.
- **Out of metric scope:** `test/**`, `scripts/**`, `bin/**`, `install/**`,
  `manifests/**`. These are governed by review, the architecture tests and the
  release checks. Scripts remain in `knip`'s project scope so dead tooling is
  still reported.
- **Generated exclusions (only these two):**
  - `src/prompts/embedded.ts` — generated by `scripts/embed-prompts.mjs`;
  - `src/version.generated.ts` — generated by `scripts/sync-version.mjs`.

  Hand-editing either is forbidden, so their generators are the reviewed surface.
  `npm run embed-prompts:check` protects the first.
- **Prompt Markdown** (`src/prompts/system.*.md`) is behavior-bearing text, not
  executable code, and is not a TypeScript module — it is outside every code
  metric while remaining exempt from cosmetic reflow.
- **Fixtures and snapshots** under `test/` are contractual data, excluded from
  duplication and code metrics.
- **Declaration/type-only code** is measured: an interface-heavy module still has
  physical lines, and type-only files still report zero function-like units.
- **Platform-only branches** are measured and are never excluded. Coverage for
  them is aggregated across the platform matrix (see *Coverage merge*).

## Physical line count

`text.split("\n")`, dropping a single trailing empty element produced by a final
newline. Blank lines and comment lines **count**. This matches
`countLines` in `test/architecture/boundaries.ts`, so the architecture gate and
the quality report never disagree about a file's size.

Comparators are exclusive upper bounds:

| Scope | Limit | Meaning |
|---|---|---|
| ordinary production source | `500` | a file must be **strictly fewer than 500** lines |
| `src/classic/**` | `400` | contributor guideline for the Classic UI |

`test/architecture/legacy-baseline.json` keeps a separate, remove-only
`1000`-line gate for frozen legacy files. It is an intermediate milestone, not
the terminal target.

## Function-like units

Counted for every complexity metric:

- `FunctionDeclaration`, `FunctionExpression`, `ArrowFunction`
- `MethodDeclaration`, `Constructor`, `GetAccessor`, `SetAccessor`

Class fields hold their initializer's function, so an arrow property is measured
as its own unit. Nested functions are measured **separately**; a parent does not
absorb a child's score. Attribution is `file#name@line`, where `name` is the
declared name, `Class.method` for members, or the variable/property it is
assigned to for anonymous functions.

## Cyclomatic complexity

`1 +` one point for each: `if`, `for`, `for…in`, `for…of`, `while`, `do`,
non-`default` `case`, `catch`, conditional expression, and each `&&`, `||`, `??`
operator. `default:` is not a decision point. Limit: `< 22`.

## Cognitive complexity

SonarSource model:

- structural increments (`if`, loops, `catch`, `switch`, conditional expression)
  cost `1 + current nesting depth` and increase nesting;
- `else if` costs `1` with no nesting penalty; a plain `else` costs `1`;
- each **sequence** of like logical operators costs `1` (so `a && b && c` is one
  increment, `(a && b) || c` is two);
- a labeled `break`/`continue` costs `1`;
- a nested function increases the nesting depth of structures inside it.

Limit: `< 22`.

## Halstead

Over the token stream of one function body, excluding nested function bodies:

- `n1` distinct operators, `N1` total operators;
- `n2` distinct operands, `N2` total operands (identifiers, literals, `this`,
  `super`, template fragments);
- vocabulary `n = n1 + n2`, length `N = N1 + N2`;
- volume `V = N × log₂(n)`;
- **difficulty `D = (n1 / 2) × (N2 / n2)`**;
- effort `E = D × V`.

Gated metric: difficulty `< 80`.

## CRAP

`CRAP = comp² × (1 − cov)³ + comp`

where `comp` is the function's **cyclomatic** value and `cov` is the fraction of
that function's covered statement lines, taken from the Istanbul-shaped
`coverage/coverage-final.json` emitted by `@vitest/coverage-v8` and joined by
source line range. Limit: `< 25`.

CRAP is only a valid gate when coverage came from a complete suite run. The
report exposes `scope.coverageLineRatio` and `scope.crapMeasured`; a partial
coverage file produces `crapMeasured: false`, and no terminal claim may be made
from it.

### Coverage merge

Coverage is `100%` of statements, branches, functions and lines in the production
scope. Platform-specific branches cannot be executed on one host, so the Phase 8
gate merges `coverage-final.json` from the Node 22, Node 24, Bun/OpenTUI,
macOS and Windows jobs before evaluating the threshold. A platform job that did
not run leaves the gate **blocked**, never passed.

## Mutation

`survived` and `no coverage` are failing statuses. Runs are bounded by module
during Phases 1-7 (`npm run quality:mutation -- --mutate '<glob>'`, with
`CLAI_MUTATION_TESTS` narrowing the test scope); the repository-wide run is a
Phase 8 scheduled/phase-close job.

Recorded runner constraint: Stryker's Vitest runner executes tests in worker
threads, and two suites call `process.chdir()`, which Node forbids there. An
unbounded dry run therefore aborts with
`process.chdir() is not supported in workers`. This is a runner limitation, not a
product defect — the same suites pass in the normal fork-based run. Bounding the
test scope through `vitest.mutation.config.ts` is the documented workaround.

## Duplication and redundancy

`jscpd` with `minTokens: 60`, `minLines: 10` over `src`, formats `typescript` and
`tsx`. Terminal target: zero reportable clones. "Redundant code zero" adds a
manual review obligation beyond clone detection: parallel implementations of one
behavior that a token comparator does not match must still be resolved — without
introducing a harmful abstraction to satisfy the metric.

## Dead code and dependencies

`knip` with entry points `src/index.ts`, `bin/*.mjs`, `scripts/**`, and every
test file; project scope `src/**` plus `scripts/**`. The two generated modules are
ignored. Optional native/platform packages (`@opentui/core-*`,
`@napi-rs/keyring`, `node-pty`, `react-devtools-core`) are listed in
`ignoreDependencies` because they are loaded conditionally per platform and would
otherwise report as unused on any single host. Terminal target: zero unresolved
production findings.

## Type-syntax classification

Token-aware, so text inside string literals and comments cannot create a
finding.

| Category | Meaning | Gated |
|---|---|---|
| `explicitAny` | any `any` annotation in production source | yes — terminal zero |
| `unknownBoundary` | `unknown` at an untrusted boundary | **no** — correct by policy |
| `unknownNarrowing` | `unknown` that still needs a predicate, schema or decoder before domain use | yes |
| `unknownInternal` | `unknown` in a purely internal position: imprecision | yes |
| `doubleAssertion` | `x as unknown as T`, `x as any as T` | yes |
| `broadCast` | `as any`, `as object`, `as Function` | yes |
| `suppression` | `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `eslint-disable` | yes |

### `unknown` is classified by syntactic position, never by name

| Position | Category |
|---|---|
| `catch (e: unknown)` binding | `unknownBoundary` |
| type argument, array element, or index-signature value (`Record<string, unknown>`, `unknown[]`, `[k: string]: unknown`) | `unknownBoundary` |
| function or method parameter | `unknownNarrowing` |
| everything else — variable, property, return type, internal alias | `unknownInternal` |

An earlier revision matched identifier names against a hint list
(`payload`, `result`, `value`, …). An independent audit demonstrated that this
let genuinely internal imprecision such as `const cachedResult: unknown` be
classified boundary-valid; because boundary `unknown` is deliberately not
ratcheted, a declaration could escape the Phase 7 gate purely by being named
well. Position is decidable and cannot be gamed by naming, so the name heuristic
was removed. `test/quality/analyzers.test.ts` keeps a regression guard using the
exact identifiers from that finding.

A reviewer may still judge a specific `unknownInternal` finding to be a valid
boundary. That judgement belongs in the phase evidence, with a narrowing plan —
not in the classifier.

The enforced gate is zero unsafe or unjustified cases, never a blindly minimized
raw `unknown` count. Boundary `unknown` may increase without failing the ratchet.

### Categories overlap deliberately

`x as any` is reported as **both** `explicitAny` (the `any` keyword) and
`broadCast` (the cast). Both are gated, so the overlap only makes the ratchet
stricter — but the counts are not a partition and must not be summed. The three
`unknown` categories *are* a partition of all `unknown` occurrences.

path, functions by `file`, then line, then name; findings by path, line, column,
category — so a diff is reviewable.

## Comparison rules

`npm run quality:ratchet` fails on:

- a file newly at or over its line limit;
- a function newly at or over a complexity limit;
- a raised maximum for any metric;
- an increased count in any gated type-syntax category;
- a loosened limit in the configuration;
- a missing metric (a crashed, timed-out or skipped analyzer is **not** green).

Legacy findings recorded in the baseline are reported and held. Baselines move
down only — `--write-baseline` refuses to write when nothing improved, so
"update the baseline to make it pass" is not an available workflow.

### A missing baseline fails; it is never auto-created

`npm run quality:ratchet` and `npm run quality:contracts` **exit 1** when their
committed baseline is absent, printing the deliberate creation command
(`node scripts/quality/ratchet.mjs --init`,
`node scripts/quality/contract-inventory.mjs --write`).

An earlier revision of the ratchet created the baseline from the current tree
when the file was missing and exited 0. An independent audit showed the
consequence: on a fresh CI checkout the gate would adopt whatever state it found
— including a regression — and always pass. `--init` additionally refuses to
overwrite an existing baseline. Both baselines must therefore be committed for
the gates to mean anything.

## Runtime budgets

| Analyzer | Budget | On exceed |
|---|---|---|
| AST metrics + type syntax | 300 s | report `measured: false`, exit non-zero |
| duplication | 600 s | fail the step |
| dead code | 600 s | fail the step |
| bounded mutation | 60 s per mutant | mutant recorded as timeout (a failing status) |

Observed at the anchor: AST metrics and type syntax complete in ~4.5 s over 630
files and ~9,000 functions; `jscpd` in well under a second per subtree; `knip` in
under a minute; the bounded mutation spike in 12 s.
